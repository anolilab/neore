# @neore/device-core-node

N-API addon around [`packages/device-core`](../device-core/README.md), built
with napi-rs. It is how the Electron shell (`apps/desktop`) reaches the Rust
device engine: pairing, the servers reached over SSH, the signed tool
manifest, executing one relayed call, the local approval and settings
commands, ACP coding-agent spawn plans and permissions, and the audit tail.

The surface is what the shell needs and nothing more. Envelope signing and
verification are not exported; they happen inside `execute`, `pair` and
`manifest`. Structured values cross as JSON strings, because the Rust serde
types are the one definition of the wire shape. Blocking work (a prompt can
wait five minutes, a shell command runs for up to ten) runs on tokio's
blocking pool, and every promise settles: a panic or join error rejects it.

## Usage

The only consumer is `apps/desktop`, which loads the addon at run time by name
so esbuild does not try to bundle the `.node` binary
(`apps/desktop/src/device/addon.ts`):

```ts
// apps/desktop/src/device/transport.ts
const DeviceCore = loadDeviceCore(); // addon.ts: require() by an assembled name
const core = new DeviceCore(dataDirectory, (json) => onEvent(JSON.parse(json) as CoreEvent), hostBundle);
```

Do not `require("@neore/device-core-node")` literally in the desktop main
process; use `loadDeviceCore`.

`index.d.ts` is the typed surface (`DeviceCore` and its methods). It is
generated by the build; `src/lib.rs` carries the doc comments it is made from.
`index.js` is committed and only picks the platform binary,
`device-core-node.<platform>-<arch>[-<abi>].node`, out of this folder. The
`.node` file itself is git-ignored.

## Building

```bash
pnpm --filter @neore/device-core-node run build
# napi build --platform --release --no-js --dts index.d.ts
```

It is a release build and it is part of the workspace's `build` graph, so
`pnpm lint:types` and `vis affected build` compile it. On Linux the keyring
backend links libdbus at build time (`libdbus-1-dev`, `pkg-config`). A change to
`src/lib.rs` that alters the exported surface changes `index.d.ts`; commit both.

There are no JS tests here. The engine is tested in `device-core`
(`cargo test --manifest-path packages/device-core/Cargo.toml`), and the
desktop's own tests cover the transport (`apps/desktop/src/device/`). CI
checks formatting for this crate too:

```bash
cargo fmt --manifest-path packages/device-core-node/Cargo.toml -- --check
```

## Things to know

- The page is a relay only. Do not add an export that signs or verifies an
  arbitrary payload; `signTurn` is the one signing export and it refuses
  anything that is not a turn post for this paired computer.
- Desktop main-process calls go through `HostTransport`
  (`apps/desktop/src/device/transport.ts`), not the addon directly.
- Design and threat model: `plans/device-execution.md`,
  `plans/ssh-environments.md`; root `CLAUDE.md`, "Native shell".
