# Coding Agents

The assistant can hand a coding task to **Claude Code** or **OpenAI Codex**. A task can also be assigned to one. The
agent runs in a fresh cloud sandbox on your own Anthropic or OpenAI API key (Settings → API keys). Each run clones the
repository, makes the change, and reports back with a summary and the diff. From there you can open a pull request.
A run can take up to 20 minutes.

## Repository setup: `.neore/setup`

A fresh clone has no dependencies installed. Commit a script at `.neore/setup` and every run executes it after the
clone and before the agent starts. The agent then begins with dependencies installed and the project built.

```bash
#!/usr/bin/env bash
# .neore/setup — runs from the repository root in every coding-agent sandbox
set -euo pipefail

npm ci
npm run build
```

- **How it runs.** If the file is executable it is run directly, otherwise with `bash`. Its working directory is the
  repository root.
- **Time limit.** Setup gets 5 minutes, which count toward the run's 20. Output goes to `/tmp/neore-setup.log`, and
  the last lines show in the run log when setup fails.
- **When it fails.** If setup exits with an error or runs out of time, the run still goes ahead. What it did install
  stays in place, and the agent is told that setup did not finish and where the log is.
- **Environment.** Only `PATH`, `HOME`, `LANG`, `TERM`, `CI=1`, `NEORE=1`, `NEORE_SETUP=fresh` and
  `NEORE_REPO_DIR` are set. Use `NEORE` to detect the sandbox.
- **No secrets.** Setup runs as a separate, unprivileged user. Your API key and GitHub credentials are not in the
  sandbox while it runs, so a script cannot read them. The agent gets the key only after setup has ended. Anything
  setup leaves running is stopped first. The script cannot change the repository's `.git` directory.
- **Changes setup makes** (a regenerated lockfile, generated code) are left out of the agent's diff and pull request.
- **Tools installed globally** go to the setup user's home and are not on the agent's `PATH`. Install what the
  agent needs into the repository instead, for example as `node_modules` or a `.venv`.
