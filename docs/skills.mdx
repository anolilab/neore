# Skills

Skills are custom AI behaviors you define once and invoke repeatedly with a slash command. Each skill packages a set of instructions, optional variables, and tool configuration — so the AI behaves exactly the way you intend for a specific task without you having to repeat yourself.

## Quick Start

1. **Open Skills**: Navigate to the Skills page from the sidebar (⚡ icon)
2. **Enable a skill**: Toggle the switch on any skill card to make it available in chat
3. **Invoke in chat**: Type `/skill-name` in the composer and press Enter

## How Skills Work

When you invoke a skill, three things happen automatically:

1. **Instructions load** — the skill's full instructions are injected into the AI's context, overriding defaults for that conversation
2. **Variables resolve** — any `{{placeholder}}` in the instructions is replaced with the values you pass
3. **Tools configure** — the skill can force a specific search mode and add or remove tools

Enabled-but-not-invoked skills contribute a short description to the AI's awareness so it can suggest using them at the right moment.

## Invoking Skills with Slash Commands

Type `/` followed by the skill's slug in the chat composer:

```
/stock-analysis ticker=AAPL
/summarize format=bullet length=short
/code-review language=typescript
```

**Argument formats:**

| Format | Example | When to use |
|---|---|---|
| Key-value | `name=John company=Acme` | Multiple variables, any order |
| Positional | `John Acme` | Skills with one or two variables |
| Mixed | `AAPL detailed` | First positional, rest by name |

The composer autocomplete shows all your enabled skills as you type `/`. Select one to insert the slug with a trailing space, then add your arguments.

## Variables

Skills can define variables using `{{variableName}}` in their instructions. When you invoke a skill, those placeholders are replaced with the values you provide.

**Example skill instruction:**
```
Analyze the {{ticker}} stock. Focus on {{aspect}}.
Provide a {{format}} report with key metrics.
```

**Invocation:**
```
/stock-analysis ticker=AAPL aspect=technical format=brief
```

**Result sent to AI:**
```
Analyze the AAPL stock. Focus on technical.
Provide a brief report with key metrics.
```

**Required vs optional variables:**
- Required variables must be provided — the skill will fail with an error if missing
- Optional variables use their default value when not provided

## Skills Library

Navigate to **Skills** (⚡ in the sidebar) to manage your skills.

### Enable and Disable

Toggle the switch on any skill card to enable or disable it. Only enabled skills:
- Appear in the slash command autocomplete
- Have their name and description injected into the AI's awareness

Disabled skills remain saved but have no effect on conversations.

### Search and Filter

- **Search**: Find skills by name, description, or content
- **Sort**: Recent, alphabetical, most used, or by creation date
- **Categories**: Filter by category (research, coding, writing, etc.)

### Import a Skill

**Import skill** accepts a `SKILL.md`, a skill `.zip` (with `references/`, `scripts/` and `assets/`), pasted markdown, or a link:

- **From a link**: paste a GitHub link to a skill folder or its `SKILL.md` (`github.com/owner/repo/tree/main/skills/my-skill`, a `blob` link or a `raw.githubusercontent.com` link), or a skills.sh link (`skills.sh/owner/repo/skill`). The server reads the `SKILL.md` and puts it in the box for the usual preview; nothing is created until you press **Import**.
- Only the `SKILL.md` comes from a link. Scripts, references and assets in the skill are not fetched; import the `.zip` if you need them.
- A skills.sh link is turned into a GitHub path by trying the usual repository layouts (`skills/<name>/`, `<name>/`, `.claude/skills/<name>/`) on the default branch. If the skill lives elsewhere, paste its GitHub link instead.
- Only public GitHub repositories are read, only over `https`, redirects are not followed, and a `SKILL.md` over 64 KB is refused. The text is untrusted: it is parsed and checked again on import, and tools the app does not have are dropped with a warning.

### Share a Bundle

A **bundle** is a chosen set of your skills, schedules or webhooks, and group chats as **one Markdown file**. Use it to hand a team the same setup, or to move your own to another account. **Export bundle** and **Import bundle** sit beside **Import** on the Skills page.

**Export.** Tick the items to share and download the file. Only items you own can be exported. A group chat brings its participants along as skills, so they count toward the skill limit below. Everything is built from a fixed list of fields, so none of these ever reach the file: API keys and encrypted values, webhook secrets and URLs, connector tokens and MCP headers, custom-endpoint (bring-your-own-key) references, variable defaults, a skill's source link, voice, and your user and organization ids. A webhook is exported without its secret, a schedule without being switched on, and neither names a bot. Tools that are not built into the app (connector and MCP tools) are left out of a skill. A skill's additional files (`scripts/`, `references/`, `assets/`) are not part of a bundle; export that skill on its own as a `.zip`. Schedules and group chats that use one of your custom endpoints cannot be exported, because another account does not have it. Event triggers are not included. The group-chat list covers your 300 most recently active chats.

**Import.** Upload the file. The server reads it and checks every item against your account as a full dry run: which free skill name it would get, whether the model is available, whether the cron expression and time zone are valid, which tools a skill adds, and whether a group chat's participants are in the file and selected. You then see a **review screen** listing each item and what it will do, and pick what to import.

- The review screen is the safety boundary. The bundle came from someone else; nothing in it runs until you turn it on. Schedules and webhooks are created **switched off**, group chats are created **without starting anything**, and skills are imported **switched off**, so none of their text joins a chat until you turn the skill on in your skill list. A group chat works once the skills it names are switched on. Tool permission modes are per user, not per skill, so a skill adds the tools listed for it and your own permission settings still apply.
- Skills are imported exactly like a single `SKILL.md`: unknown tools are dropped with a warning, and a name you already use gets a free slug (`name-2`). Schedules and webhooks go through the normal create path (the same checks and limits as the Triggers page). Group chats apply the same participant and mode checks, but are not charged to the group-chat create limit, and may name skills that are still switched off.
- A new webhook's signing secret is shown **once**, on the result screen. Copy it then; only an encrypted form is stored.
- A group chat can only be imported together with the skills it names. Selecting it selects them.
- Every text the review screen asks you to approve (a skill's description and instructions, a schedule's or webhook's prompt and task) can be expanded and read in full before you import.
- An import runs once per attempt: if your connection drops and the app retries, the second try is refused as already imported instead of creating everything twice. An import that fails is rolled back and can be tried again.
- If an item is refused while importing, everything created before it is removed again and you get the reason. Each item is its own create, so removal is best effort: if the service crashes mid-import, or removal itself is refused, some switched-off items can be left behind, and the error names them. Removal does not count against the usual delete limits, and skills that a leftover group chat still names are kept.

**Limits.** A file is at most 512 KB, and a single item at most 64 KB. A bundle holds at most 9 skills, 4 schedules and webhooks, and 9 group chats. The limits are per type, set just under the rate limit of the matching create (10, 5 and 20 a minute on the free plan), so a valid bundle does not normally hit a rate limit halfway through. If one does (for example after you created schedules earlier in the same minute), everything created so far is removed and you can retry after a minute. A free account is also held to its 5-skill limit. A file with an unknown `bundle:` version is refused.

**Format.** The frontmatter says `bundle: 1` and carries a `name` and `description`. After it comes one section per item: a `## skill: slug`, `## trigger: name` or `## group: title` heading and one fenced block. A skill's block is its `SKILL.md`; a trigger's and a group chat's are JSON. Each block is fenced with more backticks than the longest run inside it, and the reader follows fences line by line, so a heading inside an embedded `SKILL.md` is never read as a new item. Fields the format does not name are ignored on import, so a hand-edited file cannot switch an item on or add a secret.

````markdown
---
bundle: 1
name: Team starter
description: Our weekly review setup
---

## skill: paper-summary

```markdown
---
name: paper-summary
description: Summarise a paper.
---

Read the paper and list its claims.
```

## skill: critic

```markdown
---
name: critic
description: Challenge a paper's claims.
---

Look for weak evidence and say what is missing.
```

## trigger: Weekly digest

```json
{
  "cronExpression": "0 9 * * 1",
  "inputTemplate": "Summarise last week",
  "model": "gpt-5",
  "name": "Weekly digest",
  "timezone": "Europe/Berlin",
  "type": "schedule"
}
```

## group: Review panel

```json
{
  "mode": "round-robin",
  "model": "gpt-5",
  "participants": ["paper-summary", "critic"],
  "title": "Review panel"
}
```
````

## SKILL.md Format

Skills use the open **Agent Skills** standard. A skill is defined as a Markdown file with YAML frontmatter:

```markdown
---
name: Stock Analysis
slug: stock-analysis
description: Analyze stock prices and trends with financial data
category: research
variables:
  - name: ticker
    description: Stock ticker symbol (e.g. AAPL, TSLA)
    required: true
  - name: aspect
    description: Analysis focus (technical, fundamental, news)
    defaultValue: technical
    required: false
config:
  searchMode: finance
  additionalTools:
    - stockPrice
    - stockNews
  disabledTools:
    - webSearch
---

You are a financial analyst specializing in {{aspect}} analysis.

Analyze the {{ticker}} stock using the available financial tools.
Provide:
1. Current price and recent price action
2. Key {{aspect}} indicators
3. Risk assessment
4. Summary recommendation

Be concise and data-driven.
```

### Frontmatter Fields

| Field | Required | Description |
|---|---|---|
| `name` | Yes | Display name shown in the library |
| `slug` | Yes | Unique identifier used in slash commands (lowercase, hyphens only) |
| `description` | Yes | Short description shown in autocomplete and AI awareness |
| `category` | No | Groups skills in the library |
| `variables` | No | List of variable definitions |
| `config.searchMode` | No | Override the search/tool mode for this skill |
| `config.additionalTools` | No | Tools to add when this skill is active |
| `config.disabledTools` | No | Tools to remove when this skill is active |

### Variable Definition Fields

| Field | Required | Description |
|---|---|---|
| `name` | Yes | Variable name (used in `{{name}}` placeholders) |
| `description` | No | Shown to help users understand what to provide |
| `defaultValue` | No | Value used when not provided at invocation |
| `required` | No | If `true`, invocation fails when this variable is missing |

### Slug Rules

- Lowercase letters, numbers, and hyphens only
- Maximum 64 characters
- Must be unique within your account
- Reserved slugs (e.g. `system`, `admin`, `claude`) are not allowed

## Common Use Cases

### Research Skill

```markdown
---
name: Competitive Research
slug: competitive-research
description: Research a company or product competitively
variables:
  - name: target
    description: Company or product name
    required: true
  - name: focus
    description: Research focus area
    defaultValue: market position
---

Research {{target}} with emphasis on {{focus}}.

Include:
- Market position and share
- Key strengths and weaknesses
- Recent news and developments
- Competitive advantages
- Pricing and packaging

Cross-reference multiple sources and flag any conflicting information.
```

**Invoke:** `/competitive-research target=OpenAI focus=enterprise`

### Coding Review Skill

```markdown
---
name: Code Review
slug: code-review
description: Review code for issues, style, and best practices
variables:
  - name: language
    description: Programming language
    defaultValue: typescript
  - name: focus
    description: Review focus (security, performance, style, all)
    defaultValue: all
---

Review the provided code as a senior {{language}} engineer.

Focus: {{focus}}

Check for:
- Logic errors and edge cases
- Security vulnerabilities (if focus is security or all)
- Performance issues (if focus is performance or all)
- Code style and readability
- Missing error handling
- Test coverage gaps

Provide specific, actionable feedback with line references.
```

**Invoke:** `/code-review language=python focus=security`

### Writing Skill

```markdown
---
name: Email Drafter
slug: email-draft
description: Draft professional emails with the right tone
variables:
  - name: recipient
    description: Who the email is for
    required: true
  - name: tone
    description: Email tone (formal, friendly, assertive)
    defaultValue: professional
  - name: goal
    description: What you want to achieve
    required: true
---

Draft a {{tone}} email to {{recipient}}.

Goal: {{goal}}

Structure:
- Clear subject line
- Brief, direct opener
- Supporting details
- Clear call to action
- Appropriate closing

Keep it concise. Avoid jargon.
```

**Invoke:** `/email-draft recipient="VP of Engineering" goal="request headcount approval" tone=formal`

## Troubleshooting

**Issue**: Skill not appearing in slash command autocomplete
- **Solution**: Check the skill is enabled (toggle is on) in the Skills library

**Issue**: `[MISSING:variableName]` appears in the AI response
- **Solution**: The skill used `{{variableName}}` but you didn't provide that variable — re-invoke with `variableName=value`

**Issue**: Skill fails with "required variable missing" error
- **Solution**: The skill has a required variable — check the skill's variable definitions and include all required arguments

**Issue**: Can't create more than 5 skills
- **Solution**: Free accounts are limited to 5 skills. Delete unused skills or upgrade to Pro for unlimited

**Issue**: Slug validation error when creating a skill
- **Solution**: Slugs must be lowercase letters, numbers, and hyphens only, max 64 characters, and cannot use reserved words
